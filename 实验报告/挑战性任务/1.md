# 文件系统 挑战性任务 实验报告

## 任务一

### Thinking 1.1

存在以下问题：

1. 持久化问题：内存地址是运行时动态分配的，当系统重启或断电后，内存中的数据会全部丢失。如果 `f_dir` 字段存储的是内存地址，那么这个信息将无法持久化到磁盘，下次启动时将无法恢复目录关系。
2. 地址空间变化问题：同一文件控制块在不同时间加载到内存时，可能被映射到不同的虚拟地址。
3. 跨进程问题：如果文件系统服务进程和用户进程之间共享文件控制块指针，由于虚拟地址空间是独立的，两者地址不一致。

为什么当前系统不会出现这些问题：

当前 MOS 文件系统采用固定地址映射，**每个磁盘块始终映射到同一虚拟地址**，因此 `f_dir` 指针在进程生命周期内不会失效；同时 `f_dir` 仅在文件被打开期间使用，不会持久化到磁盘，且文件系统服务是单进程的，不存在跨进程地址空间问题。

## 任务四：动态缓存地址分配

### Thinking 4.1

方案设计：

采用位图（Bitmap）方案进行缓存页分配：

#### 数据结构

```c
#define CACHE_BASE 0x10000000
#define CACHE_TOP  0x50000000
#define CACHE_PAGES ((CACHE_TOP - CACHE_BASE) / BLOCK_SIZE)
#define CACHE_BITMAP_WORDS (CACHE_PAGES / 32)

static u_int cache_bitmap[CACHE_BITMAP_WORDS];
```

#### 分配算法（低地址优先）

```c
static u_int alloc_cache_page(void) {
    for (int i = 0; i < CACHE_BITMAP_WORDS; i++) {
        if (cache_bitmap[i] != 0) {
            int bit = __builtin_ffs(cache_bitmap[i]) - 1;
            cache_bitmap[i] &= ~(1u << bit);
            return CACHE_BASE + (i * 32 + bit) * BLOCK_SIZE;
        }
    }
    return 0;
}
```

#### 回收算法

```c
static void free_cache_page(u_int va) {
    u_int idx = (va - CACHE_BASE) / BLOCK_SIZE;
    cache_bitmap[idx / 32] |= 1u << (idx % 32);
}
```

#### 时间/空间复杂度分析

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|------------|
| 分配 | O(n/32) = O(n)，最坏需扫描整个位图 | 无额外开销 |
| 回收 | O(1) | 无额外开销 |
| 检查是否已分配 | O(1)（通过位运算） | 无额外开销 |

总空间开销
- 范围 [0x10000000, 0x50000000) 大小：1GB
- 每页 4KB，共有 $2^{18}$ 页
- 位图大小：$2^{18}$ bits = 32KB

选择原因：

1. 与磁盘空闲块位图设计一致：与操作系统中其他分配方案保持一致性
2. 低地址优先：位图从低位开始扫描，自然实现低地址优先
3. 回收简单：回收时只需设置对应位为 1，下次分配即可重用
4. 时间空间权衡：分配操作较慢，但空间效率高
5. **实现简单**：位图操作易于实现，且易于调试和验证

### Thinking 4.2

方案设计：

采用直接寻址表：

```c
#define MAX_BLOCKS 1024
static u_int cache_map[MAX_BLOCKS];
```

#### 映射关系

- `cache_map[blockno] = 0`：表示该磁盘块未被缓存
- `cache_map[blockno] = va`：表示该磁盘块当前缓存地址为 va

#### 操作时间复杂度

| 操作 | 时间复杂度 |
|------|-----------|
| 查找映射 | O(1) |
| 建立映射 | O(1) |
| 删除映射 | O(1) |

反向查找（虚拟地址到磁盘块号）：
由于映射表是磁盘块号 -> 缓存地址的单向关系，需要通过线性扫描进行反向查找：

```c
u_int va_to_blockno(void *va) {
    u_int page_va = (u_int)va & ~(BLOCK_SIZE - 1);
    for (u_int i = 0; i < MAX_BLOCKS; i++) {
        if (cache_map[i] == page_va) {
            return i;
        }
    }
    return (u_int)-1;
}
```

时间复杂度：O(n)
虽然反向查找较慢，但使用频率较低，整体可接受。
