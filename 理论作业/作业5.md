### 2. 死锁讨论

结论：该系统不会发生死锁。
理由：
死锁发生的必要条件之一是“循环等待”。
假设系统处于死锁状态，意味着所有 $n$ 个进程都在等待资源，且每个进程至少已持有一台打印机（否则它不会进入等待状态）。
设 $x_i$ 为进程 $i$ 已持有的打印机数，$y_i$ 为其还需要的打印机数。
在死锁状态下，所有打印机已被分配且无法满足任何进程的进一步需求：
1. $\sum x_i = m$ （所有资源已分配完毕）
2. 每个进程都在等待，故 $y_i \geq 1$。

由此可得：$\sum x_i + \sum y_i \geq m + n$。
但已知条件给出 $\sum (\text{已分配} + \text{还需要}) < m + n$，这与死锁的假设矛盾。
因此，至少存在一个进程 $k$，其 $y_k = 0$（即不再需要额外打印机），该进程可以执行完毕并释放资源，从而打破死锁风险。

### 3. 动态优先级设计

(1) 饥饿现象原因：
如果只使用静态的 `nice` 值作为优先级，当系统中不断有 `nice` 值很小（优先级高）的新进程加入时，`nice` 值较大（优先级低）的进程将永远无法获得 CPU，导致“饥饿”甚至“饿死”。

(2) 动态优先级设计：
设计公式：$Priority = nice + cpuTime - waitTime$
(注：结果越小优先级越高)

`waitTime`（等待时间）的作用：随着进程在就绪队列中等待时间变长，`waitTime` 增大，导致 `Priority` 数值减小（优先级提高）。这保证了任何进程无论初始优先级多低，最终都能因为等待时长足够久而获得执行机会，从而避免饥饿。

### 4. 同步与互斥

* 同步关系：指多个进程为了完成同一个任务，在执行次序上产生的协作关系。一个进程的执行依赖于另一个进程发送的信号或完成的结果。
* 互斥关系（Mutual Exclusion）：指多个进程因争用临界资源（如打印机、共享变量）而产生的制约关系。当一个进程进入临界区访问资源时，其他由于该资源而请求进入临界区的进程必须等待。

### 5. 银行家算法（安全性检查）

首先计算各个进程的需要的资源：
* NeedA = 11213 - 10211 = (0, 1, 0, 0, 2)
* NeedB = 22210 - 20110 = (0, 2, 1, 0, 0)
* NeedC = 21310 - 11010 = (1, 0, 3, 0, 0)
* NeedD = 11221 - 11110 = (0, 0, 1, 1, 1)

当前可用资源: (0, 0, x, 1, 2)

分析：
1. 检查谁能第一个运行：
   显然，只有 D 可能先行，必须满足 $x \geq 1$。

2. 假设 $x \geq 1$，D 执行完释放资源：
   newAvailable = (0, 0, x, 1, 2) + (1, 1, 1, 1, 0) = (1, 1, x+1, 2, 2)

3. 现在检查 A、B、C：
   * A 需要 (0, 1, 0, 0, 2)，满足。A 执行完释放资源：
     newAvailable = (1, 1, x+1, 2, 2) + (1, 0, 2, 1, 1) = (2, 1, x+3, 3, 3)
   * B、C 也可满足

因此，$x$ 的最小值是 1。
