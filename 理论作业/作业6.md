### 2. I/O 控制方式排序

四种主要类型按 CPU 干预程度从高到低排序为：
1.  程序控制
2.  中断驱动方式
3.  DMA
4.  通道技术

### 3. 场景选择与理由

场景 A（读取键盘单个字符）：中断驱动方式。
理由： 键盘输入速度极慢且具有随机性。由于数据量极小（1字节），不值得用 DMA；而中断驱动能让 CPU 在没有按键时处理其他任务，不必忙等，提高效率。

场景 B（读取磁盘 4KB 文件块）：DMA 方式。
理由： 磁盘是块设备，数据传输以块为单位，数据量较大且速率较快。DMA 可以在不占用 CPU 的情况下将一整块数据直接传送到内存，仅在传输结束时触发一次中断通知 CPU。

场景 C（连续打印 100 页文档）：通道控制方式（或 DMA 方式，取决于系统复杂度）。
理由： 面对大量且连续的输出任务，通道控制方式可以执行专门的通道指令，自主管理复杂的数据传输逻辑，最大程度释放 CPU，使其专注于计算而非管理频繁的打印任务。

### 4. 路径命名与设备独立性

(1) 程序变化：
*   物理命名： 程序会失效。因为路径中包含了具体的硬件设备名 `sda1`，硬件更换为 `nvme0n1` 后，原路径无法找到文件。
*   逻辑命名： 程序正常运行。逻辑命名通过挂载点屏蔽了底层硬件差异，用户程序无感知。

(2) 推荐方式：逻辑命名。
*   理由： 操作系统追求设备无关性。使用逻辑命名可以将用户程序与物理设备解耦，当硬件升级、维护或更换接口时，无需修改应用程序，提高了系统的可维护性和程序的移植性。

### 5. 缓冲区计算

*   单缓冲：
    *   第一块准备好并传送到用户区需 $4+1=5$ms，此时 CPU 开始处理（2ms），同时开始读第二块。因为 $T > C$，每块的处理瓶颈在 $T$。
    *   总时间 = $10 \times 5 + 2 = 52 ms$。
*   双缓冲：
    *   双缓冲允许读入和处理流程完全并行。每块处理时间 = $max(T, M+C) = max(4, 1+2) = 4$ ms。
    *   总时间 = $T \times n + M + C = 10 \times 4 + 1 + 2 = $ 43 ms。

可减少：$52 - 43 = 9ms$


### 6. SPOOLing 技术

原理： SPOOLing（外部设备联机并行操作）在磁盘上开辟输入井和输出井。
*   打印示例： 当多个用户进程请求打印时，系统并不直接把物理打印机分配给进程（打印机是独占设备）。系统接收打印请求后，将数据快速存入磁盘的“输出井”中并排队。
*   效果： 对用户进程而言，打印操作似乎已“立即可用”并完成；而物理打印机则在后台由 SPOOLing 管理程序按顺序依次打印。这样就把一台独占的物理设备虚拟成了多台可并发使用的逻辑设备。

### 7. 同步 I/O 与 异步 I/O
*   核心区别： 阶段 2（数据从内核拷贝到用户空间）是否会导致进程阻塞。
*   同步 I/O： 在阶段 1 结束后，进程在阶段 2 必须亲自参与或等待拷贝完成，即拷贝过程中进程是阻塞的，直到数据进入用户空间。
*   异步 I/O： 进程发起请求后立即返回。阶段 1 和阶段 2 全由系统完成。进程只需等系统通知“数据已在用户空间就绪”即可，在整个 I/O 期间，进程都在执行其他任务。

### 拓展思考题

MSI-X 的性能优势：
1.  负载均衡： 传统单中断所有 I/O 都由一个核心（通常是 CPU 0）处理，容易导致该核过载。MSI-X 允许将不同的 I/O 中断分发到不同的 CPU 核心上处理。
2.  减少上下文切换： I/O 线程可以和处理该 I/O 中断的核心绑定，提高缓存命中率。
3.  支持高并发： NVMe 磁盘拥有极高的 IOPS，多中断向量能充分发挥多核 CPU 的并行处理能力，消除单核处理中断的性能瓶颈。
