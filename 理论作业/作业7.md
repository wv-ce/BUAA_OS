### 1. 磁盘调度算法

（1）先来先服务（FCFS）
*   磁头移动路径：$15 \to 10 \to 35 \to 20 \to 70 \to 2 \to 3 \to 38$
*   移动总柱面数：$|10-15| + |35-10| + |20-35| + |70-20| + |2-70| + |3-2| + |38-3| = 5 + 25 + 15 + 50 + 68 + 1 + 35 = 199$
*   寻道时间：$199 \times 5\text{ ms} = 995\text{ ms}$

（2）最短寻道时间优先（SSTF）
*   磁头移动路径：$15 \to 10 \to 3 \to 2 \to 20 \to 35 \to 38 \to 70$
*   移动总柱面数：$|10-15| + |3-10| + |2-3| + |20-2| + |35-20| + |38-35| + |70-38| = 5 + 7 + 1 + 18 + 15 + 3 + 32 = 81$
*   寻道时间：$81 \times 5\text{ ms} = 405\text{ ms}$

（3）SCAN 算法
*   磁头移动路径：$15 \to 20 \to 35 \to 38 \to 70 \to 10 \to 3 \to 2$
*   移动总柱面数：$(70 - 15) + (70 - 2) = 55 + 68 = 123$
*   寻道时间：$123 \times 5\text{ ms} = 615\text{ ms}$


（4）CSCAN 算法
*   磁头移动路径：$15 \to 20 \to 35 \to 38 \to 70 \to (\text{回位至 } 2) \to 3 \to 10$
*   移动总柱面数：$(70 - 15) + (10 - 2) = 55 + 8 = 63$
*   寻道时间：$63 \times 5\text{ ms} = 315\text{ ms}$

### 2. RAID

在采用 RAID 0+1 的系统中，共有 $2\times n$ 块磁盘，分为两组，每组有 $n$ 块磁盘。
* 每组内部采用 RAID 0（条带化），只要组内的任意一块磁盘故障，整组 RAID 0 就会失效。
* 两组之间采用 RAID 1（镜像），Group 1 与 Group 2 互为镜像备份。

1. 故障情况计算：
   
* 系统中共有 $2n$ 块磁盘，随机出现 2 块磁盘故障的总组合数为：
  $$C_{2n}^{2} = \frac{2n(2n-1)}{2} = n(2n-1)$$

2. 数据未丢失的概率：
   
* 要想数据不丢失，必须保证发生故障的两块磁盘刚好属于同一组。
* 2 块故障盘在同一组的组合数为：

  $$C_{n}^{2} + C_{n}^{2} = 2 \times \frac{n(n-1)}{2} = n(n-1)$$
* 不发生数据丢失的概率为：

  $$P_{\text{安全}} = \frac{n(n-1)}{n(2n-1)} = \frac{n-1}{2n-1}$$

3. 发生数据丢失的概率 (求发生的概率)：
   
   $$P_{\text{丢失}} = 1 - P_{\text{安全}} = 1 - \frac{n-1}{2n-1} = \frac{(2n-1) - (n-1)}{2n-1} = \frac{n}{2n-1}$$

### 3. 文件系统性能

提高文件系统性能主要可以从以下五个方面进行：

1. 引入内存高速缓存（Caching）
   * 块/页高速缓存：在内存中缓存常用磁盘块，避免重复读盘。
   * 延迟写与合并写：在内存中攒够数据后再批量写入磁盘，减少写盘次数。
   * 提前读取：利用局部性原理，顺序读文件时提前将后继块读入缓存。

2. 优化磁盘布局与局部性（Locality）
   * 块组/柱面群技术：将文件的 inode、数据块及其所在目录分配在同一个物理区域，减少磁头寻道。
   * 区分配（Extent）：使用连续物理块分配（如 Ext4、NTFS），减少文件碎片，提升顺序读写速度。
   * 目录项与 FCB 分离：使目录块能装下更多目录项，加速路径解析。

3. 改进磁盘移臂调度（Disk Scheduling）
   * 采用 SSTF、SCAN（电梯算法） 或 CSCAN 对磁盘请求队列进行重新排序，最小化磁头寻道时间和延迟。

4. 加速目录检索与路由（Path Lookup）
   * 路径缓存（dentry cache）：在内存中缓存解析好的目录路径映射，避免重复逐级读盘检索。
   * 高级数据结构：在大型目录中使用 哈希表（Hash） 或 树状结构（B-Tree） 代替线性拉链，实现快速定位。

5. 采用快速一致性机制（Journaling）
   * 日志文件系统：通过先顺序写日志区、再异步写入数据区的方式提高写入效率，并在系统崩溃后实现秒级快速恢复。

### 4. 文件控制块

文件控制块（FCB）所管理的主要信息包括以下三类：

1. 基本信息（文件标识与物理结构）
   * 文件名：标识文件的字符序列。
   * 物理位置：文件在外存上的存放地址（如起始块号、索引结点号）。
   * 文件逻辑结构：是否有结构（记录式文件、流式文件）。
   * 文件物理结构：文件的分配和组织方式（连续文件、链接文件或索引文件）。

2. 访问控制信息（安全与保护）
   * 属主信息：文件创建者或当前所有者的用户标识（UID/GID）。
   * 访问权限：针对不同用户群（所有者、同组用户、其他用户）的读（R）、写（W）、执行（X）权限。

3. 使用与管理信息（元数据属性）
   * 文件属性：文件大小、文件类型（如普通文件、目录、设备文件）等。
   * 时间戳：创建时间、最后修改时间和最后访问时间。
   * 使用状态：共享计数（有多少进程或硬链接指向该文件）、锁状态等。

### 5. 文件系统

（1）60 次
*   计算检索目录的磁盘访问次数：
    *   根目录已读入内存，因此定位第二级目录不需要读盘。
    *   读取第二级目录的内容以找到第三级目录的目录项：第二级目录下有 128 个目录项。一个物理块可存放的目录项数为：$1024 / 128 = 8$ 个。要存放 128 个目录项，需要：$128 / 8 = 16$ 个物理块。平均需要查找的目录块数为：$(1 + 16) / 2 = 8.5$ 次（即读盘 $8.5$ 次）。
    *   读取第三级目录的内容需要读盘 1 次。
    *   检索目录阶段平均读盘次数为：$8.5 + 1 = 9.5$ 次。
*   计算访问文件数据块的磁盘访问次数：
    *   文件采用串联（链接）文件方式组织，平均大小为 $100\text{ KB}$，需要 100 个数据块。
    *   访问串联文件的第 $i$ 块需要从头开始读入前 $i$ 块。平均访问一个块需要读入的数据块数为：$(1 + 100) / 2 = 50.5$ 次。
*   答案：
    访问文件 `f` 中的一个块平均需要访问磁盘：$9.5 + 50.5 = \mathbf{60}$ 次。

（2）7.5 次

采用 i 节点方式。

文件名占 14B，i 节点指针占 2B，因此一个目录项大小为：$14+2=16B$

每个磁盘块可存放目录项数为：$1024/16=64$
根目录的 i 节点已在内存中。
访问第三级目录下文件的一个块：

1. 读根目录数据块，根目录只有 usr1、usr2、usr3，1 个块即可：1

2. 读第二级目录对应的 i 节点：1

3. 第二级目录有 128 个目录项，需要：128/64=2 个磁盘块，平均查找需要：$\frac{2+1}{2}=1.5$

4. 读第三级目录对应的 i 节点：1

5. 每个第三级目录下文件数不超过 50 个，一个块可放 64 个目录项，所以读第三级目录数据块：1

6. 读目标文件的 i 节点：1

7. 采用直接索引访问文件数据块，读目标数据块：1

总次数为：

$
1+1+1.5+1+1+1+1=7.5
$

（3）8 MB

计算磁盘地址所占字节数：
*   系统最大容量为 $16\text{ ZB} = 16 \times 2^{70}\text{ B} = 2^{74}\text{ B}$。
*   物理块大小为 $1\text{ KB} = 2^{10}\text{ B}$。
*   系统包含的物理块总数为：$2^{74} / 2^{10} = 2^{64}$ 块。
*   指向块的物理地址（块号指针）需要 $\mathbf{8}$ 字节（$64\text{ bits}$）来表示。

计算最大支持的文件大小：
*   FCB 中的索引区大小为 $512$ 字节，允许采用一级索引组织。
*   一个物理块作为一级索引块，可存放的地址项个数为：$1024\text{ B} / 8\text{ B} = 128$ 个。
*   FCB 的索引区直接存放了索引块的地址指针，由于索引区大小为 $512$ 字节，每个指针占 $8$ 字节，则最多可以存放 $512 / 8 = 64$ 个一级索引指针（对应 64 个一级索引块）。
*   文件包含的最大数据块总数为：$64 \times 128 = 8192$ 块。
*   最大文件大小为：$8192 \times 1\text{ KB} = 8192\text{ KB} = \mathbf{8\text{ MB}}$。
